# 全双工自问自答保护（2026-09-18）

## 问题与处理

用户实用反馈：设备播放的回答又被ASR当作下一句输入。此前单次AES安静通过不足以说明实际环境不会误识别。
已先静音中止循环。保留全双工/AES，增加文字侧疑似回声隔离；未改系统音量、麦克风增益或固件。

EchoGuard只比较近期TTS播放文本，NFKC归一化并忽略标点/空格/大小写；exact子句匹配含短词，
5字以上允许1次编辑、10字以上最多2次编辑（错/漏/插字）。候选上限512、参考3条各2048字、35秒TTL。
重复播放文本更新TTL，播放中每5秒刷新当前文本。超长/改写很多的ASR不一定会匹配，不能声称完全阻断所有回声。
只在实际播放/3秒尾部、或此轮ASR起音与播放重叠时检查；ASR句子结束晚于播放仍保留本轮重叠标记。

疑似partial不放入“听到的新一句”；疑似final进入echo_suspect提示，不入pending、不发reply，不自动请求千帆。
用户可忽略，或明确确认后正常排队一次。确认/忽略绑定递增候选ID，过期按钮不能误提交后来另一句。
真正重复助手的话、短词或只改一两个字的用户输入也可能被拦住，所以保留确认路径，不静默丢弃。
静音/断开清理候选与参考，播放、听取不同的新话、待回复队列逻辑保留。

## 验证

- EchoGuard 6项：exact、子句、错漏字、不同内容、过期、界限/去重。
- core 12项：旧双工流程外，增加疑似不提交不排队、partial不冒充新输入、确认一次/忽略、过期候选拒绝、
  播放结束但ASR仍在本轮时继续检测、不同的真人新话可正常排队。
- release/asan companion回归各21组通过（release在新增过期替换用例前，asan包括该用例）。

用户授权的15秒真实安静测试，临时用纯AEC施压（生产AES不变）：onset3、partial0、final0、reply1、
疑似计数0、pending0、errors=[]，结束关麦。不出现回声识别，所以不能用这一轮声称“实际拦截成功”。

板端数字回灌（无麦克风/扬声器/云端）：公开固定WAV既作为回复内容，又直接输入真实RKNN ASR，
模拟AEC失效；真实core处理实际ASR消息。onset1、partial9（播放模拟期6）、final1、echo_suspicions1、
pending0、reply_requests1（只有初始固定回复），errors=[]。这证明测试中的完整回灌句被隔离，不会引发第二轮。
probe只打印计数，不保存PCM或识别全文。声学对齐根因尚未确定：当前参考来自aplay管道写入时刻，并非ALSA硬件采样时钟，
可能受缓冲/启动/重采样延迟影响；源码检查不能把这种可能性当作已定位的唯一原因。

## 交付

应用备份rtctrl-companion-before-echo-guard.tar.gz；保持原full_duplex=true/aec_enable_aes=true配置。
板端部署应用，无新增常驻模型；候选文字和近期播放参考只在内存。交付保持麦克风关闭。
后续日常验收关注是否仍有未匹配回声、确认误拦频率和不同音量摆位的影响。
