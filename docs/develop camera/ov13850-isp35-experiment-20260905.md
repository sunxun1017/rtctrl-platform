## 曝光时序：已有依据与未解决部分

驱动 `ov13850.c` 的 2112×1568 模式：HTS 寄存器 0x380c/d=0x12c0，VTS 0x380e/f=0x0680，g_frame_interval 返回 10000/300000。
`OV13850_PIXEL_RATE` 为 `300MHz × 2 × 2 lanes / 10 bits = 120MHz`，来自链路速率公式，不足以证明它等于内部曝光时钟。

SDK `rkaiq/hwi_c/aiq_sensorHw.c:1341` 的 `SensorHw_getSensorDescriptor()` 明确优先调用 `_SensorHw_getSensorFps()`，按 HTS×VTS×FPS 计算时钟，失败才回退到 PIXEL_RATE。`SensorHw_getBlank()` 读取 hblank/vblank 的最小值。C++ `hwi/SensorHw.cpp` 也有相同优先路径。
因此成功读取帧间隔时，AIQ 的等效时钟是 239616000 Hz，行周期为 1/(1664×30)=20.03205us，而不是 120MHz/4800 推出的 40us。
**239.616MHz 是算法归一化时序量，不是已经实测的 PLL 时钟。**驱动 g_frame_interval 使用静态 mode->max_fps，未来若放开动态 VTS 必须再次审计；首阶段固定 30FPS，避免依赖该路径的动态帧率行为。

驱动 exposure 控件以整行为单位，下发时 `ctrl->val << 4` 写 0x3500..0x3502，低四位为小数。IQ 不再重复做 ×16。Time2Reg=[0,0,1,0.5]、LinePerReg=1 对应整行四舍五入。实测 AE 30ms 对应 1498 行，与该路径吻合；后续 API 实测已确认 pclk=239.615997、HTS=4800、VTS=1664、FPS=30；物理曝光脉冲仍需测量。

仍缺：OV13850 revision B2 的可信完整 PLL/HTS 单位规格、实际 0x0300..PLL 寄存器读回、光学曝光时间测量。不能据现有结果补改 HTS/pixel_rate；本次不交付内核时序修正。

## 增益与限制

`rkaiq/uAPI2/rk_aiq_user_api2_custom_ae.c:214..264` 提供公开转换实现：
`regGain = clamp(int(C1 * pow(gain,M0) - C0 + 0.5), minReg, maxReg)`。
旧 IQ [1,15.5,16,0,1,16,248] 对应 1/2/4/8/15.5 倍 → 16/32/64/128/248。驱动将该控件拆成高低字节写 0x350a/b。
这是**公式和驱动接口**的一致性验证；内置 AE 核心为库实现，仍以板端控制行为交叉验证，不能把公开 custom AE 实现冒充完整内置算法源码。

sensor Dgain 固定 1；ISP Dgain 第一阶段也固定 1，避免混淆两者。旧 IQ 的两帧 delay 仅为实验参考，未做逐帧阶梯测量。
旧 IQ 最小曝光 4、最大 VTS-4 与本驱动 2、VTS-16 不一致，已按当前驱动调整，未盲目整体复制。

### 复位后自动白平衡诊断取得有效结果

复位后IP169.254.127.31，节点重新确认 sensor subdev5、ISP media4/video31/stats36/params37，2112x1568 NV12。直接用系统原库v6.0x31.0、setListenStrmStatus(true)完成两轮STOP/DEINIT。无需加载独立构建库即可进行本轮AWB实验。

no-adjust（借用白点范围保留，关闭增益调整/offset/单色处理）白点=0、converged=0，输出参考增益约1.855/2.038。all-pixels（再关闭色度过滤和光源权重）白点统计非零、converged=1，自动增益R=1.64117,B=1.20288；等待180帧后的白纸ROI(800,500,400,400)，R/G=0.967263，B/G=0.986318，无ROI裁剪。此为算法自动输出，不是固定测量增益。all-pixel白点统计可能包含重叠光源累计，不能把WPTotalNUM直接理解为独立白点像素数。
