# 原 4.19 板控 MCU 接口：事实与独立实现边界

2026-10-03，依据已备份的原 Image、现场选定符号、原 `mcu_tool` 静态分析以及
Android/独立 Linux 对照，建立首个可独立实现的缓存 ABI。
证据和复现入口：[本轮记录](../../../../outputs/rk3568-mcu-baseline-20261003/README.md)。
此说明不是完整 MCU 规格，也不把反汇编解释当作实际 MCU 应答。

## 先区分接口

| 接口 | 已核实事实 | 当前边界 |
| --- | --- | --- |
| `/dev/McuCom` | 字符 10:61；I²C5 fe5e0000、5-0062，McuCom 驱动；DT `smdtmcu,STM8S00K3` | 板控电源/看门狗路径；物理 MCU 型号与固件版本未测 |
| `/dev/ttySMT0` | 字符 4:64；fdd50000.serial；参考应用普通动作使用 115200/8N1 | 与 GD32 的实物对应、真实命令语义/ACK 未验 |
| `/dev/ttySMT4` | 字符 4:68；fe680000.serial；参考应用用于升级 | 不用升级 UART 做普通动作测试 |
| `/dev/rjgt102` | 前阶段 JNI 静态依赖该路径，现场节点未出现 | 加密/客户接口线索，不能并入 McuCom 或电机协议 |

参考应用 commit `ed91ef7486cdebca00aa32d497f5aa45cb226c0e` 的版本 1.0.0 和部分电量为硬编码。
普通发送封装接受任意低八位 cmd，并没有可信的只读查询白名单；回调仅打印长度，
弱 ACK 检查第五字节不够定义完整响应契约。命令 14 在随机动作中出现，未证实为安全停止。
网络断线处理里未发现 MCU 停止请求；这只能说明已检查参考调用链，不能推断硬件没有其它保护。

## 仅适用于指定原 Image 的缓存 ABI

Image 长度 33046536，SHA-256：
`54e75d6dbb03ab96ea938eb940fe64cab91f3f81a3e43a9e98d763980dd7779d`。
内核版本标签 4.19.232 本身不能标识驱动实现。

| 项目 | 静态确认的行为 |
| --- | --- |
| open / release | 返回 0，不发 I²C、不改 GPIO/看门狗 |
| request | 原始 ioctl 数字 `0xc0`；编号本身未编码缓冲长度 |
| 输入 | 用户指针必须指向完整、可读写的 **65 字节**；入口 copy_from_user 读取整块 |
| 输出 | 缓存 `mcu_data+16..21` → 用户缓冲 `[32..37]`，随后 copy_to_user 返回整块 |
| 其它字节 | 该分支保留输入，独立程序预先全部清零 |
| 返回 | 正常路径为 0；错误路径不能假定遵守完善的标准 errno 契约 |
| 硬件效果 | 该分支没有 I²C/GPIO/看门狗调用；没有读取物理 MCU |

独立 [C 诊断程序](../../../../outputs/rk3568-mcu-baseline-20261003/read-cached-mcu-info.c)
只接受显式 `/dev/McuCom`，以 O_RDONLY/O_NOFOLLOW/O_NONBLOCK/O_CLOEXEC 打开，
核验字符设备，零初始化 65 字节，仅调用一次 0xc0，打印六字节后关闭。
没有利用原厂家用户态代码或库；原驱动内核二进制仍在调用链中。

同一程序在 Android 及独立 Linux 都输出 `MCU_CACHE_BYTES=000000000000`。
这六字节的业务解释未独立确认，不称为 MCU 真正版本/健康/电量；不让读取成功充当硬件自检成功。
程序没有内部 Image 指纹检查，调用者必须事先核验本驱动和绑定。换内核、同名节点、
兼容驱动、打开其它设备或新增 ioctl 都需要重新审计和对照。

## `skip-mcu` 为什么重要

本次 Android 和独立 Linux 的运行 FDT 均包含零长度 `skip-mcu`。
原 probe 把它视为布尔 true，设置内部 skip 标志，完成 sysfs 设置后返回；
绕过身份/版本初始化、看门狗启用及工作线程创建。
这是原驱动的分支行为，不是物理 MCU 是否存在的检测结果。

在该标志下，原寄存器读写 helper 会返回 255，并且不执行总线操作；读 helper 不填充调用者字节。
部分上层代码用低八位返回值大于 1 判断成功，因而 255 也可能产生“成功”日志。
之前关机记录里的写标志日志不能单独证明真的向 MCU 写入或获得 ACK。
同样，跳过内核喂狗并不能证明 MCU 自身看门狗当前关闭或不保留历史状态。

本轮两个约 30 秒被动 trace 窗口没有 I²C5/0x62 的事件，UART0/4 计数未变；
第二个窗口的调度正对照有事件且零丢失。这与 skip 路径一致，但仍只是观测窗口，
不是物理总线长期监测，也不能证明 MCU 无活动。

## 非 skip 路径的寄存器事实（仅静态分析）

以下是原驱动代码意图，没有在本轮执行这些写入或取得 MCU 应答，不能直接作为试发菜单。

| 路径 | 原代码中的操作 | 未验证部分 |
| --- | --- | --- |
| 原 mcu_tool `notify_power_on` / ioctl 0xaa | 寄存器 0x51 写 0x33 | 标志实际影响、ACK、重复调用 |
| ioctl 0xab /断电路径 | 寄存器 0x51 写 0x55 | 断电时机、电源轨、存储协调 |
| 看门狗启用/关闭 | 寄存器 0x32 写 1 / 0 | MCU 超时、复位对象、跨 reboot 状态 |
| 喂狗 | 寄存器 0x33 写 0xab | 成功应答、调度容限 |
| probe 身份检查 | 读 0x3a，尝试匹配 0x56/0x89 | 物理芯片身份、固件适配 |
| `mcu_get_version` | 读 0xfb–0xff 五字节 | 返回字符串是否真实、字节定义 |

写 helper 以 `[reg,value]` 两字节消息执行 i2c_transfer，最多五次。
普通寄存器随后读回 `(reg-0x80)&0xff` 比较；喂狗不读回。
读 helper 使用 i2c_smbus_read_byte_data。失败时旧值可能保留，不能靠比较值或成功日志建立可靠 ACK。
这些重试不是已经完成的电气故障恢复设计。

普通 probe 的身份匹配失败不一定阻止后续初始化：失败后的 sysfs 路径仍可能继续版本/看门狗/线程。
启用看门狗失败也可能继续创建 worker。worker 有约一秒 sleep 和计数 >18 的喂狗分支，
这是代码调度，不是已测得的 MCU 硬件超时。
版本 helper 忽略部分读取错误并返回 0，初始化为零的内容可能看起来像有效版本。
另一缓存初始化存在比对失败后的递归路径，不应原样复制为无界的开源实现。

shutdown/restart 路径按原因和板型分支执行关闭看门狗/写断电标志；
其中 `3566X` 字符串比较并未证明使用的是 DT 的 model。
物理验收应分别覆盖正常关机、reboot、内核交接和故障情况，见
[POWER-LIFECYCLE.md](POWER-LIFECYCLE.md)。

## 离线复核定位与公开边界

选定符号与已备份 Image 对应，文件偏移为符号 VA 减原 `_text`。
这些偏移仅适用于上面的 SHA，不对另一版本保证：

| 函数/分支 | Image 文件偏移 |
| --- | --- |
| MCU_close | 0x4945c0 |
| 寄存器写/读 helper | 0x494670 / 0x494938 |
| mcu_get_version / mcu_run_thread | 0x494df8 / 0x494f20 |
| mcuinterface_probe | 0x4954e0 |
| MCU_ioctl / 0xc0 分支 | 0x495bc8 / 0x496300 |
| WatchdogOff / PowerOff helper | 0x496810 / 0x4968d8 |
| mcuinterface_shutdown / MCU_open | 0x496c98 / 0x496d38 |

公开接口描述、独立代码和脱敏结果；原二进制、原始反汇编、私有参考源码及原机标识不打包公开。
没有把无许可的参考 Jar/源码按本仓库许可重新分发。
后续源码内核的适配应自行实现：有界错误处理、真实 ACK、失败/失联行为、生命周期次序，
并用同输入对照验证。缓存诊断通过只是这个过程的第一项用户态成果。

## 2026-10-04 源码 Linux UART0 枚举与完整参考审查

用户明确电机未接。仅启用UART0的独立DTB配同一实测5.10 Image及新版RAM initramfs上板，
实际 fdd50000.serial 绑定dw-apb-uart，设备为ttyS0、4:64、console=N；GPIO0_C0/C1实际归uart0所有。
十秒窗口及收尾tx/rx=0，FD快照为空。未打开物理TTY或发送应用动作；这些不证明电气零TX、
真实GD32接线或反馈有效。串口probe及/proc寄存器诊断仍可能改变硬件状态。
源码codec和POSIX PTY测试在这个内核再次通过，当前仍只链接测试，不接生产控制HAL。

完整锁定参考树的167 Java+1 AIDL已检查，缺失114个blob只在内存读取并核Git对象/pack哈希。
新增业务调用确认欢迎5、告别10、音乐26、唤醒1/25、随机12–15/21–24及FA原值，
但这些是应用触发条件，不能推导关节、停止、单位或去使能。厂家UART Binder/JNI实现仍缺，
唯一AIDL为provisioning；没有可信运动状态解码或安全停止契约。

升级程序接收消息URL下载到应用外部files/downloads，再走ttySMT4；它是否升级同一电机MCU未确认。
当前两个下载目录路径均ENOENT，完整源码树的5个bin仅有语音资源命名；未读取那些二进制，
不能证明板卡其他位置或MCU内部没有固件，也没有执行下载或升级。
具体来源/调用行/对象覆盖见[完整参考审计](../../../../outputs/rk3568-motor-alignment-20261004/reference-audit.json)，
实机及剩余边界见[本轮结果](../../../../outputs/rk3568-motor-alignment-20261004/README.md)。
