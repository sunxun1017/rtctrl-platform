# rtctrl 开发协作

若用户要自己动手、请求教学或源码导读，改用 [rtctrl-mentor](../rtctrl-mentor/SKILL.md)
决定指导深度；本 skill 只补充工程约束，不自动实现用户的练习。明确直接实现请求仍按下面流程执行。

## 先建立需求与现场

从用户当前请求提炼目标行为、涉及层次、验收依据；用简短中文说明理解后执行。
IDE 打开的文件只是线索，不自动扩大任务范围。对可逆实现细节采用符合现有代码的合理假设；
缺少会改变接口或目标硬件的必要信息时，先完成独立调查，再问最关键的问题。

先检查 `git status --short` 和相关差异，识别用户在研内容；不清理、不恢复、不顺带修复无关文件。
读取根目录 `CONTRIBUTING.md`、相关目录约定，并按
[项目地图](references/project-map.md)定位源码和 ADR。
文档描述目标架构，源码和 CMake 决定当前实现；有冲突时明确指出差异，不能默默选择方便的解释。

## 实现与验证

- 核心契约由所属模块维护，具体 SDK/系统 I/O 留在适配器，产品由 apps/products 装配。
  修改稳定端口时按 CONTRIBUTING 更新对应 ADR。
- 实时循环保持固定容量、有界执行，避免动态分配、锁、文件日志、异常传播和无界阻塞。
  采集、RKNN/ISP 和模型管理不进入 1 kHz/200 Hz 实时线程。
- 从实际 CMake 依赖确认修改文件参与哪个目标；目录存在、IDE 无红线或无关 preset 通过均不证明它已构建。
- 按 [验证指南](references/verification.md)选择必要检查。修复行为问题时验证触发条件、失败路径和回归；
  不为 Markdown 或简单低风险修改强行新增代码测试。
- 完成时说明结果、实际运行的验证、尚未覆盖的硬件或环境边界。不要把计划执行的命令写成成功结果。

## 子 agent 协作

当任务可拆成独立调查/实现/审查且主 agent 同时有有效工作时，请使用子 agent。
主 agent 保留需求裁决、共享接口修改、整合与验收；简单问题不要求组队。
按 [子 agent 分工](references/delegation.md)委派。角色定义位于仓库 `.codex/agents/`；
skill 内 `agents/openai.yaml` 仅是界面元数据，不是子 agent 注册文件。

## 在开发中持续完善

任务结束前检查是否获得值得复用的新证据：用户明确纠正、稳定偏好、可复现故障根因、
已验证构建/板端流程，或实际架构变化。若有，直接在本次授权开发范围内作小幅更新并说明；
只沉淀项目知识，不修改全局配置或扩大执行授权。用户要求不更新时遵从。

- 通用协作决策更新此入口；条件性技术经验更新 references；架构事实优先更新原有 docs/ADR，skill 保留链接。
- 项目经验写入 [已验证经验](references/lessons.md)：日期、适用条件、证据路径/命令、结论、失效条件。
- 临时进展与尚未证实猜测留在任务记录，不作为已验证经验。不得保存凭据、完整对话或本机私有路径。
- 合并重复条目，删除已失效规则；更新旧知识而非无限追加。只由主 agent 整合 skill 修改。
- 复查链接、frontmatter、角色定义一致性。重大流程变更用独立子 agent 对真实场景做只读演练，
  检查其实际决策，不能只检查是否出现某些词句。

这是会话内基于证据的维护流程，依赖 agent 实际读取并修改文件，不是后台自动学习或模型训练。
开源组织方式与配置依据见 [来源](references/sources.md)，仅在维护 skill 时读取。
