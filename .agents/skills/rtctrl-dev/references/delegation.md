# 子 agent 分工与交接

| 自定义角色 | 独立任务 | 返回内容 |
| --- | --- | --- |
| `rtctrl_architect` | 只读追踪端口、依赖、执行域和 CMake 接线 | 路径/符号证据、影响面、需修改的契约 |
| `rtctrl_hardware` | 只读核查 RKNN/V4L2/总线/BSP 与 SDK 版本约束 | 所有权/格式/ABI 问题、本机与板端验证边界 |
| `rtctrl_reviewer` | 只读核对最终差异、需求覆盖、失败路径与验证证据 | 有证据的问题、严重性、复现条件；无发现则明说 |

使用宿主支持的自定义 agent 调用能力。若当前 spawn 工具只能接收任务文本，读取对应
`.codex/agents/<角色名>.toml`，把其中职责和本次任务作为消息传入；不要假设配置已经加载。
若根本没有子 agent 工具，主 agent 顺序完成这些检查并说明，不用 shell 启动嵌套 AI 绕过工具限制。
角色继承当前模型与权限，不固定模型、不提升权限、不递归组建团队。

给每个任务写清：目标、原始用户要求中的相关内容、允许读取/修改路径、输入和已知约束、
验收标准、需返回的证据。独立审查不灌输预期结论。
初始通常只需 1–2 个子 agent，服从宿主并发限制；等待时主 agent 继续独立工作。

默认由主 agent 编写实现。确有可并行的独立实现时可委派通用 worker，并指定互斥文件所有权；
共享头、顶层 CMake、skill/经验文件由主 agent 串行整合。禁止两个 agent 同时改同一文件或同一构建目录。
子 agent 不提交、不推送、不部署、不修改任务外配置；返回建议不会扩大原任务授权。
主 agent 阅读实际 diff 与验证输出，解决分歧后交付，不能仅转述“子 agent 说通过”。
