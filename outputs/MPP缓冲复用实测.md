# MPP 缓冲复用实测（2026-09-12）

在 RV1126B 上对独立视频预览做了三组测试。摄像头输入 NV12 2112×1568，JPEG 输出 960×712，质量参数 75，max-pending=1，zero-copy-pkt=true。每组预热超过 60 帧，采样约 20 秒，使用一个板内 MJPEG 消费者，同时开启 ftrace 分配计数和 GStreamer latency tracer。

| 指标 | 系统原插件 | 重编译，复用关闭 | 重编译，复用开启 |
|---|---:|---:|---:|
| FPS | 30.155 | 30.161 | 30.155 |
| CPU（单核为 100%） | 33.69% | 34.44% | 33.84% |
| DMA heap 分配次数 | 604 | 604 | 0 |
| DMA heap 释放次数 | 603 | 603 | 0 |
| 管线平均延迟 ms | 13.791 | 14.011 | 13.780 |
| 管线 P95 延迟 ms | 14.601 | 14.515 | 14.320 |
| 两进程 RSS 合计 KB | 40652 | 41736 | 40280 |

同一个重编译插件开启复用后，分配次数降为零，但 CPU 只降低约 0.60 个百分点，相对约 1.75%。一次短测不足以把这个小幅差异认定为稳定收益。与系统原插件相比，CPU 没有下降。每帧申请缓冲区的问题已经验证，尚不能据此声称整体性能大幅提升。

修改位于 SDK 的 gstmppenc.c：将 gst_mpp_allocator_set_cacheable 的 FALSE 参数改为环境变量 RTCTRL_MPP_REUSE 是否等于 1。这里 cacheable 指缓冲池保留复用，并非改变 CPU cache 属性，也没有删除 DMA 缓存同步。预热后的 0 次分配不意味着启动时不申请内存。分配和释放相差一次可能来自采样边界，不代表泄漏。

构建使用 SDK 源码、交叉编译器、MPP/RGA 头文件，以及板端运行库。GStreamer 开发头文件为 1.22，运行库为 1.24.11，因此单独保留系统原插件对照。首次手工构建遗漏 -fvisibility=hidden，导致 MPP 与插件的 mpp_enc_debug 同名符号冲突；gdb 定位后补上 SDK 原有编译选项，最终三组测试完成。

测试插件独立存放于板卡 /userdata/rtctrl-video-preview/reuse-test/plugins。通过 GST_PLUGIN_PATH 和独立 GST_REGISTRY 选择，系统插件没有替换。最终已恢复系统原插件在 8080 端口运行，状态帧数持续增长，snapshot.jpg 可获取。未把试验配置设为默认。

原始结果：mpp-reuse-results.json。板端完整日志目录：/userdata/rtctrl-video-preview/reuse-test/results-1609522304。板端时钟不准，目录时间戳不作为实际测试日期。

这次验证覆盖固定分辨率短测和进程退出，没有覆盖长期运行、慢客户端、动态分辨率、浏览器端到端延迟或图像逐像素一致性。RSS 也不代表所有 DMA 内存占用。下一步应比较复用开关下的 perf 热点，继续定位 V4L2 回队时的缓存维护和 IOMMU 映射开销；不能直接删掉这些同步操作。

## 后续复测与输入路径确认

| 顺序 | 状态 | FPS | CPU，单核为 100% | CPU ms/帧 |
| --- | --- | ---: | ---: | ---: |
| 1 | off-1 | 30.061 | 35.49% | 11.805 |
| 2 | on-1 | 30.057 | 32.55% | 10.828 |
| 3 | on-2 | 30.063 | 33.55% | 11.159 |
| 4 | off-2 | 30.059 | 35.73% | 11.887 |
| 5 | off-3 | 30.057 | 35.28% | 11.738 |
| 6 | on-3 | 30.059 | 34.29% | 11.407 |

六轮中，OFF 的平均 CPU 占用为 35.50%，ON 为 33.46%；每帧 CPU 时间从 11.810 ms 降到 11.131 ms，按两组均值计算约减少 5.75%。这比第一轮更支持复用有小幅收益，但还谈不上大幅提速。画面来自实时摄像头，JPEG 大小略有变化，并非固定录像逐帧回放。

四轮带追踪复测，OFF 申请次数为 604、605，ON 均为 0。无详细追踪的六轮不能直接与开启 perf 的 CPU 结果混算。

一次性日志确认输入有两个 DMA-BUF GstMemory（3311616 和 1655808 字节），RGA 源使用 virtual-address。复用开启时的调用栈仍经 RGA 的 rga_mm_map_buffer、rga_dma_map_sgt 到 rk_iommu_map；cache clean 同时存在于 RGA、DMA-BUF 结束 CPU 访问和 V4L2 QBUF 路径。因此池复用不能消除输入合并、映射和全部缓存维护。

原始材料保存在 mpp-reuse/clean-1609522688 与 mpp-reuse/repeat-1609522539。系统插件哈希复核未变，原预览已恢复。
