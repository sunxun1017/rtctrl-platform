无详细追踪的两组均值：CPU 从 29.84% 降到 10.80%；CPU 时间从 9.925 ms/帧降到 3.596 ms/帧，当前短测中约减少 63.8%。

第一轮 NM12 的 perf 有 587 个 cpu-clock 样本，NV12 有 227 个，两轮都没有丢样本。原来 `queue0:src` 中的 libc 地址 `0x9ddd4` 占 16.01%，`rk_iommu_map` 占 10.22%；NV12 这一轮不再看到 queue0:src 的该 libc 热点，也没有采到 `rk_iommu_map`。这表示它们不再是本次采样里的热点，不能写成内核绝对不再调用这些函数。

单内存后 `__arch_copy_from_user` 的 Self 排到 19.38%。继续展开，实际是：

```text
gst_video_encoder_finish_frame → gst_pad_push
  → writev → __arm64_sys_writev → pipe_write
  → copy_page_from_iter → __arch_copy_from_user
```

至少这条栈能归到编码输出写入管道，不能记成摄像头整帧拷贝。后续可以单独比较 JPEG 输出缓冲的访问方式，或减少进程间交接，但这轮没有改它；JPEG 每帧约 49 KB，已经不是前面约 4.97 MB 的原始输入规模。

通过隔离gst-launch的格式枚举筛选验证方向，未设为默认。系统MPP不变；保留Python分帧优化。图像目视未见明显平面错位，未做长期稳定性或色卡验证。
